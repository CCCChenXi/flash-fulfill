# FlashFulfill 项目简历亮点

> 定位：后端业务开发 | 独立完成 | 模型/模块开发 | 不虚标性能数据

## 项目简介

**FlashFulfill —— 分布式高并发秒杀与订单履约平台**（独立完成）

基于 Spring Cloud Alibaba 的微服务架构，设计并落地「秒杀 → 建单 → 扣库存 → 智能派单履约」完整业务链路，覆盖秒杀大促核心痛点：**高并发防超卖、请求幂等、跨服务一致性、削峰填谷**。拆分为网关、秒杀、订单、库存、履约、用户、商品、事件转发 8 个服务模块，每服务独立数据库、独立部署，采用 RocketMQ 事件驱动 + 同步调用协作，全链路最终一致。

## 技术栈

Java 21 · Spring Boot 3.3.5 · Spring Cloud Alibaba（Nacos / Sentinel）· RocketMQ · Redis 7 · MySQL 8 · MyBatis-Plus · JWT · 雪花 ID

## 核心技术亮点

### 1. 秒杀状态机与幂等设计

用一次 Redis Lua 原子脚本完成「请求幂等占位、SPU/SKU 双状态校验、限购计数、库存扣减」，将秒杀入口的多次读写收敛为一次原子操作，杜绝多实例并发下的重复下单与超卖；同一 requestId 在 TTL 内严格幂等，业务按 0~6 状态码语义化返回。

### 2. 扣库存与发消息的一致性设计

针对「库存已扣但 MQ 已发、客户端超时误回滚」的时序漏洞，将扣库存与写建单事件放入同一 Lua 原子完成，事件写入 Redis Stream，由独立 relay 服务消费并手动 ACK 转发 RocketMQ——成功才 ACK、失败留 pending 重投，消费端靠 requestId 幂等去重，实现 **at-least-once 且不重复下单**，消除分布式状态下的一致性窗口。

### 3. 分层防超卖与最终一致

秒杀入口 Redis 预扣作为流量闸门，DB 层用**单条条件 UPDATE（乐观锁）**原子扣减兜底，双重保障不超卖；Redis 预扣与 DB 库存解耦，预留对账补偿机制保证最终一致。

### 4. 领域模型与状态机流转

SPU/SKU 两级商品模型；订单采用「INITIAL → CREATED → DISPATCHED / FAILED / CLOSED」状态机，跨服务通过 RocketMQ 事件驱动状态推进，订单侧以 requestId 幂等键 + 数据库唯一约束双重去重。

### 5. 模块分层与边界意识

各服务独立库独立部署，公共契约（Result / 错误码 / MQ 消息 / DTO / ID 生成）收敛到公共模块；参数校验分层（网关鉴权 → Controller 层 Bean Validation → 共享 DTO 注解兜底），避免跨模块硬编码与逻辑重复。

### 6. 基础设施能力

雪花算法分布式唯一 ID（多实例不撞、趋势递增、时钟回拨保护）；Sentinel 网关限流（IP / 用户维度，规则 Nacos 热更新）；库存服务启动时 pipeline 批量将 DB 库存加载到 Redis。
